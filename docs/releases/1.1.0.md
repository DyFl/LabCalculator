# Lab Calculator 1.1.0

Prepared November 20, 2026 as a **draft full release for review**, not a published prerelease. GitHub's prior public history contains only 1.0.0, 1.0.1, and 1.0.2 Preview 1; there is no earlier full release. Version 1.1.0 uses Android version code **4**.

## Changes since the latest published APK

- Redesigned all five calculators with filled inputs, blue/slate light and dark themes, teal results, selected tab pills, and an All calculators menu. Primary actions, presets, copy controls, and formula/working disclosures have clearer roles.
- Fixed ignored rapid return-tab taps. Stable viewport and Calculate state reduce unnecessary form recomposition while keeping the latest input values and keyboard/error/result scrolling.
- Added explicit mg/L and µg/L families alongside PPM/PPB, exact quantity-preserving unit changes within compatible families, and confirmed reset/re-entry across incompatible families. No density or parts-per basis is inferred.
- Dilution now gives a complete stock-transfer/final-volume instruction, uses µL below 1 mL, and distinguishes exact quantities from approximate display rounding while retaining exact working.
- Preset status and record preservation, validation, saved state, and MS/MSD preparation/measurement workflows include improvements made before the redesign but not previously shipped in an APK.

The established formulas and scientific assumptions remain in force; no QC acceptance limits, purity correction, accounts, analytics, or internet access were added. This is a calculation aid, not laboratory or regulatory validation. See [calculation assumptions](../calculation-assumptions.md).

## Responsiveness evidence

Earlier Pixel 9 Pro measurements found optimized number-entry p95 app-frame completion decreased from 11.84 to 8.21 ms in the controlled workload, about 31%. These November 14 warm-workload measurements are not new measurements of this final APK or direct touch-to-display latency. Tab rendering did not measurably improve from the code changes; the ignored-return-tap correctness fix is separate. Method, debug/optimized differences, data, and limits remain in [the responsiveness report](../responsiveness.md).

## Release verification

- 100 JVM calculation, parsing, unit, and preset tests passed in a forced fresh rerun.
- The complete 57-test Compose/application regression suite passed on BlueStacks Android 9 / API 28 at 360 dp and 1.3× text (279.932 s), using an isolated application ID.
- On Pixel 9 Pro / Android 17, the first full attempt was **56/57**, failing `CalculatorStateTest.formulaDetailsAreOptionalAndExpansionSurvivesRestoration` immediately after a disclosure tap. Its entire state class then passed **9/9** in isolation. A second uninterrupted full run, using the same APKs and assertions, passed **57/57 in 231.708 s**. No app workaround or weakened assertion was applied. Intermittent test/tap timing remains a testing limitation; its cause was not proven.
- The older November 14 Pixel result remains **51/57**, followed by a separate **10/10** workflow-class pass. The six original hierarchy failures and their names remain documented. Later passes do not rewrite either failed full run.
- A separate black-box test app passed against the **actual optimized release APK** on Android 9 (one comprehensive test; final artifact rerun recorded in release metadata). It checked Dilution, RPD, conversion/swap, MS/MSD, Molarity, result/step clipboard contents, preset save/load/delete, Next sample's retained preparation/cleared measurements, and saved-task restoration after background process termination with a changed process ID.
- Debug, instrumentation, and optimized release builds passed. Lint: **0 errors; 14 debug and 13 release warnings** in the release-preparation reports. Warnings are maintenance items; no blanket suppression was added.

The standard 57-test suite uses controlled Compose hosts. It does not run on the minified binary. The separate [binary smoke harness](../../tools/release-smoke/README.md) drives its UI without importing production internals. An initial attempt to pair the debug test APK with the R8 app failed during runner startup because of a removed Kotlin runtime class; no calculator assertion ran. The standalone harness also required corrections for off-screen zero-bounds labels and separate label/editor nodes before its passing run. Those diagnostic attempts are not counted as passing tests.

The first parallel test build was intentionally stopped under host memory pressure, before UI execution. A sequential rebuild and complete run succeeded. Local raw outputs are retained under ignored `build/release-1.1.0/`; they are not source files or release assets. Test stores are isolated, phone timeout and emulator display settings were restored, and the phone's everyday app was never replaced or cleared.

One independent read-only reviewer inspected the earlier failures, calculation/preset diff, callback freshness, signer history, release configuration, and smoke-test expectations. The main agent verified its substantive findings and executed the final checks. No confirmed calculation, saved-data, or normal-use defect was found that blocks preparing this draft.

## APK and installation

The draft asset is **LabCalculator-v1.1.0.apk**, built using `assembleRelease` from the commit tagged **v1.1.0**. It is R8 optimized and non-debuggable, uses **com.dyfl.labcalculator**, version **1.1.0 / 4**, min SDK **24**, target SDK **37**, and has no Performance profiling overlay. Source archives are not installable Android apps.

The final APK's SHA-256 and exact source commit are recorded in the attached **SHA256SUMS.txt** and **RELEASE-METADATA.json**. The APK also embeds AGP's version-control record. Container hashes change when that commit metadata changes, so a final checksum is deliberately not hardcoded into a source file that would itself change the commit.

The signer deliberately remains the **historical local Android debug certificate**, retained for update continuity, rather than a newly created production key. Its public SHA-256 certificate digest is `3a759b32e907bf2188a02f0bbd99db89892082696b3b31efca0551567fececc8`. The APK's non-debuggable flag is independent of that certificate's origin. No keystore or passwords are committed or attached. A fresh clone normally has a different local key and must not be assumed to produce an interchangeable update.

All three published APKs were downloaded and their signatures, identity, versions, and published file checksums independently checked. Compatibility for the two published updates is established by those APK properties; each old published binary was not separately upgraded on a fresh device. An existing same-package code-3 emulator installation accepted the code-4 update without uninstalling. The final binary's synthetic preset save/load/delete and process-restoration checks passed. No test used or claimed to migrate a user's real saved presets.

For 1.0.1/1.0.2, install the approved release APK over the existing app to retain its storage. For 1.0.0, **do not uninstall or clear data to work around the certificate mismatch**; keep that installation if its state matters. Automatic cross-certificate data migration is not provided. Android 7.0 is the configured minimum, not a claim of a completed Android 7 device test.
